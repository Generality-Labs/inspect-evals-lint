### Added

- `ruff_rules_enabled` (IECQ007) warns when the ruff configuration governing a package does not enable a rule in a curated set of ruff rules that matter for evaluations. The set starts with `PLW1514` (unspecified-encoding); each entry carries its justification on the rule page. The check asks ruff rather than parsing its configuration: it lints a snippet the rule reports as though it were a file in the package, so `select` prefixes, `extend-select`, `ignore`, `extend`, `per-file-ignores`, `preview` and `explicit-preview-rules` apply as ruff applies them. A preview rule selected by a prefix while preview is off counts as not enabled. A repository with no ruff configuration gets ruff's defaults, which enable none of the set. The message names the configuration file and how many violations ruff would report under the source root with the rule on. The rule uses the `ruff` package installed alongside the linter, else `ruff` on `PATH`, and skips when there is neither; ruff is not a runtime dependency. It also skips, with ruff's reason, when ruff cannot load the configuration, and a failing ruff is tried once per configuration in a run. A repository declines an entry with a reason under `[tool.inspect-evals-lint.ruff_rules_enabled] declined`, and the finding is then reported as suppressed ([#64](https://github.com/Generality-Labs/inspect-evals-lint/issues/64)).

### Changed

- A rule can mark a diagnostic as `shared` when it is about something several packages share, such as a repository-wide configuration file. A run lists an identical shared diagnostic once, under the first package that reports it, and each other package records a `skip` for the rule naming that package. The mechanism is opt-in: only `ruff_rules_enabled` uses it, and every other diagnostic stays with its package even when its text matches another package's, so no other results change.
