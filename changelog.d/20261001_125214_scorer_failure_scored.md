### Added

- `scorer_failure_scored` (IEBP012) reports a scorer that turns a grader or sandbox failure into a score. It flags a broad handler (`except:`, `except Exception`, `except BaseException`) with no `raise`, whose `try` awaits a grader call (`.generate(`, or an outside call named for a judge or grader) or a sandbox `.exec(`/`.read_file(`. The handler must return a constant (`0.0`, `False`, `None`, `""`, a module-level or imported upper-case name such as `INCORRECT`, a tuple starting with one, `Score(value=<constant>)`), assign one to a name returned later, or rebind a name the `try` sets, to a constant or a dict holding a bool or number, that is read after the `try`. A handler that then leaves by `continue` or a non-constant `return` such as `Score.unscored(...)` is not reported, and neither is a `None` the code tests with `is None` or `not`. Only code a scorer runs is read: `@scorer` functions, the functions nested in them, and the package functions they call at any depth, across the package's modules. `@tool` functions, solvers and probes are not read, and a package helper that swallows its own failures is not reported again at its callers. A narrowed handler such as `except FileNotFoundError` is not reported. It is an error around a grader call and a warning around a sandbox call, since a missing file or a timeout can be the agent's fault. The hint recommends letting the error propagate, or `Score.unscored(reason="grader_failed")`/`"scoring_failed"`. Method calls on instances or parameters are not followed yet ([#56](https://github.com/Generality-Labs/inspect-evals-lint/issues/56)).
